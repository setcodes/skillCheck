# Как предложить вопрос или правку

Общий банк вопросов живёт в этом репозитории. Сайт собирается из него, поэтому вопрос появляется у всех
только после того, как попал сюда и прошёл вычитку. Импорт на странице «Импорт / Экспорт» меняет банк
лишь в браузере того, кто импортировал.

Есть два пути:

- **Без git** — [создайте issue «Предложить вопрос»](https://github.com/setcodes/skillCheck/issues/new?template=question.yml),
  заполните форму, и мейнтейнер перенесёт вопрос в банк. Так же сообщайте об ошибке в ответе.
- **Через pull request** — если готовы сами отредактировать JSON. Порядок ниже.

## Где лежит контент

| Что | Файл | Схема |
|---|---|---|
| Вопросы теории | `src/shared/questions/frontend.json` | `src/shared/bank/schema.ts` |
| Задачи «что выведет код» | `src/shared/quiz/frontend.json` | `src/shared/bank/quiz-schema.ts` |
| Кейсы: ревью и live coding | `src/shared/cases/frontend.json` | `src/shared/bank/case-schema.ts` |
| Темы вопросов | `src/entities/question/model/topics.ts` | — |

Поля вопроса описаны в [README банка](src/shared/questions/README.md), заготовка —
[question-template.json](src/shared/questions/templates/question-template.json).
Backend, аналитика и DevOps заморожены в `/frozen` и в сборку не входят.

## Pull request с вопросом

1. Сделайте форк, установите зависимости (`npm install`) и создайте ветку `feature/<что-меняете>`
   от `dev`.
2. Скопируйте объект из шаблона в конец `src/shared/questions/frontend.json` и заполните его:
   - `id` — `fe-<тема>-NNN`, следующий свободный номер в теме. Уже опубликованный id не меняйте:
     к нему привязаны оценки и ссылки. Если переименовать всё же нужно, старый id идёт в `aliases`.
   - `topic` — id из справочника тем; новую тему сначала добавьте в `topics.ts`.
   - `level` — `junior | middle | senior`, `kind` — `screening | deep | practical | architecture`.
   - `answer.full` — ответ так, как его стоит произнести вслух; `mustMention` — чек-лист для
     интервьюера: что обязательно должно прозвучать.
   - `reviewedAt: null` — дату вычитки ставит мейнтейнер, не автор.
   - `author` — ваш ник, если хотите указать авторство.
3. Если у вас уже есть вопросы на сайте, добавленные через импорт, нажмите там «Экспортировать мои
   правки»: файл содержит только ваши вопросы и уже в формате банка — объекты из `questions`
   можно переносить в `frontend.json` как есть.
4. Проверьте:
   ```bash
   npm run validate-questions
   ```
   Ошибки схемы валят CI; предупреждения — это контентный долг, их можно оставить.
   Полная проверка перед PR — `npm run check`.
5. Откройте pull request в ветку `dev`. Workflow `Validate Questions` прогонит ту же проверку
   и не пропустит PR с ошибками схемы.

## Правка существующего вопроса

Исправления ошибок и неточностей — сразу PR. Кардинальную переделку ответа сначала обсудите в issue.
В описании PR укажите, что было не так, и по возможности дайте источник (MDN, спецификация,
документация библиотеки).

## Чего ждём от вопроса

- Реальный вопрос с собеседования, сформулированный так, как его задаёт интервьюер.
- Ответ проверяемый и без воды: факты, а не «зависит от ситуации» без пояснений.
- Пример кода — там, где без него ответ непонятен.
- Русский язык, термины — как их произносят на собеседовании.
- Не копировать чужие материалы целиком; источники — в `sources`.

## Код

Для изменений кода — та же схема: ветка `feature/*` от `dev`, `npm run check` перед PR.
Как устроен проект — в [README](README.md).
