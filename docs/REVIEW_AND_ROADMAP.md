## 2. Рамки проекта (решения)

1. **Активна только профессия Frontend.** Backend Java, Analyst, DevOps — в интерфейсе видны как карточки «Скоро» (disabled), маршруты и данные не загружаются. Их контент (`*-qa-100.json`, `tasks/{backend,analyst,devops}.ts`) остаётся в репозитории, но вынесен из рабочей сборки и дорабатывается позже по одной профессии.
2. **Хостинг свой, не GitHub Pages.** Домена пока нет, всё делаем и проверяем локально; публикация — отдельным шагом, когда появится домен.
3. Из этого следует:
   - не нужны раннеры Java/Python/SQL/YAML/Dockerfile/Mermaid → из активной сборки уходят `java-parser`, `sql.js`, Pyodide (CDN), `mermaid`, `js-yaml`; закрываются R4, R5, R6, R7, R8, S2 (по крайней мере до возвращения этих профессий);
   - остаются JS/TS-задачи и теория, значит главный риск — **выполнение JS кандидата** (R1–R3) и качество контента Frontend (C1–C3, C7, C8);
   - привязка к GitHub Pages (`base: /skillCheck/`, `404.html`, `deploy.yml`) убирается, вместо неё — настраиваемый `BASE_URL`, контейнер и конфиг веб-сервера.

**Решение по хостингу: VPS.** Значит, возможен небольшой бэкенд, и роли становятся настоящими (закрывает S1): эталонные ответы теории и `solution` задач не входят в публичный бандл, а отдаются API только вошедшему интервьюеру. Бэкенд минимальный: Node (Hono/Fastify) + SQLite, один контейнер за Caddy с авто-HTTPS. Данные кандидатов по-прежнему остаются в браузере, если не включена серверная синхронизация (см. Фазу 7).

| 4 | Контент Frontend: 100 ответов, +15 задач, e2e | 2–3 недели |
| 5 | Дизайн (параллельно с хвостом Фазы 4) | ~2 недели |
| 6 | Docker/Caddy/CSP/SEO/VPS-харденинг, готовность к публикации | 4–5 дней |
| 7 | Бэкенд: вход интервьюера, эталоны и скрытые тесты на сервере | 1–1.5 недели |

Итого ≈ 6–8 недель одним разработчиком. Критичный путь: 0 → 1 → 2 → 3 → 7; контент (4) и дизайн (5) идут параллельно после 3; Фаза 6 — после 1, финальная проверка — после 7.

## 5. Метрики готовности (Frontend)

- `npm run check` (typecheck, lint, tests, validate, build) зелёный; покрытие раннера и банка ≥ 80 %; один e2e-сценарий.
- 100 % задач Frontend: `solution` проходит, `starter` нет; `eval`/`new Function` вне воркера — ноль.
- `answer.full` ≥ 400 символов у всех 100 вопросов, `mustMention` и `reviewedAt` заполнены.
- ≥ 36 задач, ≥ 10 на каждый уровень.
- Стартовый бандл < 300 КБ gzip; Lighthouse a11y/perf/SEO ≥ 95.
- Контейнер собирается и работает на `localhost:8080` без внешних запросов (кроме явно разрешённых).
- Эталонные ответы и `solution` отсутствуют в публичном бандле и в ответах API без входа интервьюера (проверяет e2e).
- Включение любой замороженной профессии — одним флагом без правок ядра.
