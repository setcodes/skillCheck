## 1. Что исправлено

### 1.1. Баги в эталонных решениях задач

Каждый баг подтверждён запуском; под каждый добавлена скрытая проверка, которая ловит старый эталон.

### 1.2. Движок проверок

- `assert.deepEqual` в сценарных проверках сравнивал через `JSON.stringify`: порядок ключей влиял на результат, `NaN` равнялся `null`, `Date` — строке. Теперь используется тот же структурный `deepEqual`, что и в декларативных проверках (`src/shared/runner/core.ts`).
- Проверка, которая никогда не завершается (промис без resolve), ждала общего таймаута воркера в 5 с и уносила результаты **всех** проверок. Теперь у каждой проверки — своя и `script`, и `call` с `satisfies` — тайм-аут 2 с, остальные выполняются.
- В сценарии работала только `const { x } = m` с одним именем: `const { a, b } = m` и `import { a, b as c } from 'MODULE'` ломались. Теперь модуль приходит параметром `m`.
- Промис в сообщениях об ошибке печатался как `{}` — теперь `«Promise»`.
- Тесты на всё это — в `tests/runner.test.ts`.

## 2. Замечания и предложения

Приоритеты: **P1** — заметно влияет на качество интервью или безопасность, **P2** — качество и поддержка.

### 2.1. Контент

1. **P1. Поля схемы пустые во всём банке.** `commonMistakes` заполнены у 2 вопросов, `redFlags`, `followUps`, `sources` и `tags` — ни у одного, `reviewedAt` — `null` у всех 159. Интерфейс и фильтр по тегам работают вхолостую. Ответы для бывших заглушек написаны мной и требуют вычитки человеком.
   *Предложение:* заполнять, начиная с `followUps` — они нужнее всего на собеседовании, либо убрать неиспользуемые поля из UI; после вычитки проставлять `reviewedAt`. В `validate-questions` перевести «нет `mustMention`» и «нет `full`» из предупреждений в ошибки — сейчас их ноль, и новые заглушки не должны появляться.
2. **P2. Тема «Тестирование» — 4 вопроса**, меньше порога в 5; уровень junior не покрыт в темах «Браузер и сеть», «Производительность», «Безопасность», «Тестирование».
3. **P2. Описания задач первой волны однострочные** («Разбить массив на чанки.», «Кэш с вытеснением LRU.»), а граничные случаи раскрыты только в скрытых тестах. Кандидата штрафуют за поведение, которое нигде не оговорено: `chunk` при `size <= 0`, `uniqueBy` с `undefined` и `null`, `diffShallow` с ключом-`undefined`, `memoize` с результатом `undefined`.
   *Предложение:* в каждом описании одной строкой перечислить граничное поведение, которое проверяют скрытые тесты (как уже сделано для `groupBy`, `buildTree`, `parseQueryString`).
4. **P2. Оставшиеся слабые места эталонов** (не исправлены, потому что выходят за описанный контракт): `memoize` по `JSON.stringify` — `f(undefined)` и `f(null)` дают один ключ; `flatten` через `push(...spread)` упадёт на массиве в сотни тысяч элементов; `buildPostsView` вернёт `userName: undefined` для несуществующего автора; `diffShallow` считает `NaN → NaN` изменением; `curry` не поддерживает функции с параметрами по умолчанию (`fn.length`).
5. **P2. Кейсы `case-live-todo`, `case-live-modal`, `case-live-infinite-scroll`** — без стартового файла и эталона, в отличие от остальных live-кейсов.
6. **P2. У сценарных проверок нет `title`.** «Показать тесты» выводит сырой код с `import * as m from 'MODULE'`. Стоит дать каждой проверке название и показывать его над кодом.

### 2.2. Песочница и безопасность

1. **P1. Кандидат может «пройти» любые тесты.** Решение и движок проверок выполняются в одном realm воркера, поэтому код вроде `Object.is = () => true` или подмены `Object.keys` и `Array.prototype.some` ломает сравнение в `deepEqual` и `assert`. Интервьюер видит код, поэтому это не P0, но вердикт «все тесты пройдены» становится недоверенным.
   *Предложение:* в `checks.ts` и `core.ts` захватывать ссылки на встроенные функции при загрузке модуля (`const ObjectIs = Object.is` и т. д.) и заморозить ключевые прототипы (`Object.freeze(Object.prototype)`, `Array.prototype`, `Function.prototype`) до запуска кода кандидата.
2. **P1. Остался канал в сеть.** `lockDownScope` убирает `fetch` и `WebSocket`, но не может закрыть динамический `import('https://…')` — это синтаксис, а не глобальный объект. `WebTransport` тоже не в списке.
   *Предложение:* ограничить воркер через CSP (`script-src 'self'`, `connect-src 'none'` для воркера через заголовки или `<meta>`); добавить `WebTransport` в `BLOCKED`.
3. **P2. Синхронный бесконечный цикл уносит все результаты.** Воркер убивается целиком, кандидат видит только «Превышено время».
   *Предложение:* слать результат каждой проверки отдельным сообщением; при таймауте supervisor возвращает уже полученные и помечает зависшую проверку.
4. **P2. `crypto.randomUUID()` есть только в secure context.** На деплое по http (не localhost) `runWithWorker` упадёт. Нужен запасной вариант через `crypto.getRandomValues`.
5. **P2. `assert` в сценариях не бросает исключение,** в отличие от `node:assert`: после проваленной проверки сценарий продолжается и часто даёт каскад `Test execution error`. Счётчик «пройдено N из M тестов» считает отдельные assert, а не проверки. Стоит либо бросать при провале, либо явно задокументировать.

### 2.3. Данные и приложение

1. **P1. Импорт банка навсегда перекрывает встроенные задачи.** `exportBank` выгружает весь банк, а `importBank` сохраняет в overlay каждый элемент, даже идентичный встроенному. После цикла «экспорт → импорт» все 38 задач становятся локальными переопределениями, и исправления эталонов и тестов из релиза (как эти) до пользователя уже не дойдут.
   *Предложение:* экспортировать только overlay; при импорте пропускать элементы, совпадающие со встроенными (сравнивать после нормализации схемой, не через `JSON.stringify` с разным порядком ключей); в DataHub показывать «локально переопределено N задач» с кнопкой сброса.
2. **P2. `MockPage` пишет сессию в localStorage 4 раза в секунду** (`saveSession` на каждый тик таймера по 250 мс). Достаточно сохранять при изменении значимых полей или раз в несколько секунд — метка времени и так восстанавливает таймер. Там же прямой `localStorage` в обход `shared/storage`, `as any` для профессии и устаревший `document.execCommand('copy')`.
3. **P2. 59 предупреждений линта**, из них 16 `label-has-associated-control` (реальные проблемы доступности форм), 4 `exhaustive-deps` в `MockPage`, 15 `any`, 20 неиспользуемых переменных. *Предложение:* `eslint --max-warnings <текущее число>` в CI и снижать его.
4. **P2. Форматирование не проверяется.** `npm run format` есть, но в CI нет `prettier --check`; `MockPage.tsx` и файлы задач отформатированы вразнобой (пробелы после `{`, в конце строк).
5. **P2. Размер бандла.** Главный чанк — 796 КБ (220 КБ gzip), в него входит весь JSON банка вопросов и задач. Парсеры prettier уже грузятся лениво; банк стоит тоже вынести в отдельный чанк, загружаемый при входе в профессию.
